# Handoff Report — Explorer 1 Survey: Architecture (R1) & Hardening (R4)

## 1. Observation

1. **`app.js` Line 1 Syntax Error**:
   - File: `app.js:1-2`
   - Content:
     ```javascript
     import { setupTasksController } from './src/tasks/controller.js';\nimport { vaultBlobGet } from './src/vault/store.js';
     import { vaultBlobGet } from './src/vault/store.js';
     ```
   - Verbatim Error from `npx playwright test tests/smoke.spec.js`:
     `SyntaxError: Invalid or unexpected token` across all 19 views.

2. **Missing Symbol References in `app.js`**:
   - `vaultBlobGet`: Called directly at `app.js:4945` and `app.js:4969` as an undeclared identifier, and passed into `setupTasksController` at `app.js:3462`.
   - `getSearchTasksHay`: Called at `app.js:10197` and `app.js:10588`, but not defined anywhere in the codebase.
   - `getSearchVaultHay`: Called at `app.js:10136` and `app.js:10221`, but not defined anywhere in the codebase.
   - `VaultStore`: Referenced 10 times at `app.js:4871`, `4872`, `4873`, `4874`, `4875`, `4876`, `4878`, `4884`, `4983`, `5109` (`VaultStore.vaultHost`, `VaultStore.vaultSort`, `VaultStore.vaultTypeLabel`, `VaultStore.vaultTagSet`, `VaultStore.vaultCardHTML`, `VaultStore.vaultRowHTML`, `VaultStore.vaultWidgetHTML`, `VaultStore.vaultViewHTML`, `VaultStore.vaultModalHTML`, `VaultStore.vaultLinkPickerHTML`), but `VaultStore` is NEVER declared or assigned in `app.js`.

3. **`src/tasks/controller.js` Syntax and Identifier Corruptions**:
   - Double-dollar selector mangling: `app.$app.$` at lines 47, 1032, 1035, 1082.
   - Template string corruption: `app.${...}` at lines 185, 187, 197, 203, 213, 214, 215, 994, 1001, 1004, 1011.
   - Broken CSS inline styles: `` `height:app.${topPad}px;flex-shrink:0` `` (lines 185, 187) evaluating to `"height:app.120px"`, invalidating spacer heights and breaking virtual scrolling.
   - State and attribute corruption: `'empty-app.state'` (line 175) and `data-status-body="app.${status}"` (line 170).

4. **`scripts/postbuild.js` and `manifest.webmanifest`**:
   - File `scripts/postbuild.js` is CommonJS (`const fs = require('fs')`).
   - `package.json` specifies `"build": "vite build && node scripts/postbuild.js"`.
   - `index.html` has `<link rel="manifest" href="manifest.webmanifest">`.
   - Vite builds `manifest.webmanifest` into `dist/assets/manifest-BWm-CJgl.webmanifest`.
   - `vercel.json` line 31 targets `/assets/(.*).webmanifest`.

5. **Modals and Inert Implementation**:
   - `openModal` (`app.js:1177`) and `closeModal` (`app.js:1188`) do not manipulate `inert` on `#view-root`.
   - `openModal` does not save or restore `document.activeElement`.
   - `openModal` does not set `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, or trap focus with Tab/Shift+Tab.

## 2. Logic Chain

1. From **Observation 1**, `app.js:1` contains an unescaped literal `\n` in a module script. Because the script cannot parse, the entire JS runtime fails before `renderView` or router can run, causing all smoke tests to fail with `Invalid or unexpected token`.
2. From **Observation 2**, even if the syntax error is fixed, invoking search or idle indexing triggers `ReferenceError: getSearchTasksHay is not defined` and `ReferenceError: getSearchVaultHay is not defined`; visiting `#vault` triggers `ReferenceError: VaultStore is not defined`; invoking file operations triggers `ReferenceError: vaultBlobGet is not defined`.
3. From **Observation 3**, `src/tasks/controller.js` was generated by a global string replacement script (`do_extract.js`) that did not use boundary guards on `$` vs `${` and `$$`. This resulted in broken CSS (`height:app.120px`), runtime errors on `app.$app.$`, and corrupted text outputs.
4. From **Observation 4**, PWA requirements mandate consistent manifest resolution at `/manifest.webmanifest`. Vite's default hashing into `dist/assets/manifest-<hash>.webmanifest` requires configuring `rollupOptions.output.assetFileNames` or `publicDir`, renaming `postbuild.js` to `.cjs`, and aligning `vercel.json`.
5. From **Observation 5**, accessible modal requirements (and `tests/a11y-modal.spec.js`) require dialog semantics, focus trapping, focus restoration, and setting `inert` on `#view-root` during modal display.

## 3. Caveats

- Vitest unit tests currently pass (342/342 in 24 test files) because unit tests isolate pure helpers in `src/` rather than evaluating `app.js` end-to-end.
- The full Playwright test suite (beyond `smoke.spec.js` and `a11y-modal.spec.js`) will require `app.js` to successfully boot without console errors before downstream behavioral assertions can be verified.
- Code splitting and chunk budget optimization (R2) will need to be applied after `app.js` and module extractions are cleanly decoupled.

---

## 4. Conclusion

The application failures are completely categorized into:
1. **P0 Boot Blockers**: Literal `\n` in `app.js:1`, undefined `VaultStore`, `vaultBlobGet`, `getSearchTasksHay`, `getSearchVaultHay`.
2. **P0 Task Controller Corruptions**: In `src/tasks/controller.js`, remove all `app.$app.$`, `app.${...}`, `'empty-app.state'`.
3. **P1 Hardening (R4)**:
   - Rename `scripts/postbuild.js` -> `scripts/postbuild.cjs`.
   - Configure Vite `rollupOptions` / public asset configuration to keep `/manifest.webmanifest` unhashed at root.
   - Update `openModal` / `closeModal` and `openSearch` / `closeSearch` in `app.js` with full dialog semantics, focus trap/restore, and `#view-root` `inert` toggling.
4. **P1 Sync & Performance (R3)**:
   - Optimize `src/lib/merge.js` signature from O(N log N) JSON serialization to cheap `updatedAt` + `length` comparison.
   - Add iteration loop guard in `src/habits/store.js`.
